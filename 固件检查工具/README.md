# 固件文件检查工具

独立的 Windows 桌面工具。使用 Python 标准库实现，无运行时第三方依赖。

## 启动

直接双击本目录的 `固件文件检查工具.exe`，不需要安装 Python。

如果要从源码运行，安装 Python 3.10 或更新版本后，在本目录运行：

```powershell
python main.py
```

`打包.bat` 会在本项目创建独立虚拟环境、安装构建依赖、生成图标，并重新打包单文件 EXE；构建时需要能访问 Python 包索引。

## 功能

- “工程分析”是主页面：“选择文件”打开一个 Windows 原生选择窗口。选中文件夹或文件后点击窗口中的“选择”，程序根据路径自动分析文件夹、ZIP、BIN、Intel HEX（`.hex` / `.ihx`）、ELF（`.elf` / `.axf` / `.out`）、map 文件。也可以将文件夹或 ZIP 拖进窗口；拖入只填写路径，点击“开始扫描”后才读取文件。ZIP 直接读取条目，不解压到磁盘。
- “固件对比”是独立页面：选择或拖入两个有地址数据的固件文件，按地址查看变化。单个文件拖到 A/B 卡片会填入对应栏；同时拖入两个文件会依次填入 A、B。
- 显示原始文件大小、CRC32、SHA-256，以及可定位镜像的地址范围和有效字节数。
- 从文件名或可读内容中尝试识别常见芯片型号、版本字符串。未识别到时明确显示“未知”或“未发现”。ELF 同时显示 `e_machine` 架构。
- HEX 校验逐行 checksum，支持扩展段地址与扩展线性地址；ELF 读取 `PT_LOAD` 的文件数据。
- 对两个 BIN/HEX/ELF 文件逐地址比较，显示新增、删除、修改的连续区间、字节数和前 16 字节，可导出 CSV。
- GNU ld map 显示输出节及 `Memory Configuration` 中的 Flash 链接区上限；Flash 占用按位于 Flash 区域内的输出节地址并集估算。Keil/Arm map 读取 `Load Region` 的 `Size` 和 `Max`。同名 AXF/HEX/BIN 可借用 map 的链接区上限计算镜像量比例。

工程扫描会跳过虚拟环境、Git 元数据及常见缓存目录；单文件上限 128 MiB、累计读取上限 512 MiB、候选文件上限 3,000 个。超过上限会在界面提示。

扫描期间可点击“终止扫描”，界面会保留已经找到的结果，主按钮随后变为“继续扫描”，从尚未处理的文件或目录接着扫描。修改工程位置后，按钮变回“开始扫描”，从新位置重新开始。扫描持续超过 8 秒时会提示缩小扫描范围；选择整个磁盘通常会比选择具体工程目录慢很多。

扫描过程中，已完成解析的文件会立即加入结果列表。拖入新的文件夹或 ZIP 时，程序会先结束旧扫描并清空旧结果；确认新路径后，由用户点击“开始扫描”。

扫描主要读取目录和候选固件文件，不修改它们。选择整个磁盘会增加磁盘读负载并可能暂时影响电脑速度；通常选择具体工程目录更合适。

## 地址与占用说明

BIN 不带地址，需正确填写加载基址；默认 `0x08000000` 只是常见示例。两个 BIN 使用不同基址时，差异会按实际输入地址计算。

工程扫描不会替 BIN 猜测地址，表格会显示“未确定”。同一工程的 ELF、BIN、HEX 可能只是同一固件的不同输出格式，不能把它们的大小相加当作 Flash 用量。

“镜像数据”是实际有字节的段总量，不是地址范围跨度。HEX 地址空洞不计入占用或差异。ELF 仅使用 `PT_LOAD` 的文件数据，BSS 不计入。没有 map 容量信息时，“Flash 镜像量”只是估计，可能包含 RAM 初始化数据；目标芯片和版本号也是启发式识别结果。

map 文件不含完整镜像字节，可查看布局和占用估算，不能参与字节级比较。目前解析 GNU ld 与常见 Keil/Arm map 格式；其他链接器的布局信息可能无法识别。界面中的“链接区上限”来自链接配置，不一定是芯片物理 Flash 总容量，也可能只是应用程序分区大小。

界面最多显示 10,000 个差异区间，汇总字节数仍统计全部差异。CSV 导出当前显示的区间。
